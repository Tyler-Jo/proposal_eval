# 테스트 기능 구현 워크플로

## 적용 범위

새로운 Python 모듈, Test 01~07, 통합 테스트, POC 측정 코드를 구현하거나 변경할 때 적용한다.

## 작업 순서

1. `docs/current_state.md`에서 현재 우선순위와 블로커를 확인한다.
2. `docs/project_description.md`와 `docs/unit_test_poc_plan.md`에서 대상 기능의 요구사항과 검증 계층을 확인한다.
3. 입력·출력 데이터 계약과 실패/경계 조건을 먼저 정의한다.
4. 1~5페이지 수준의 최소 fixture와 Fake OCR/LLM을 만든다.
5. 단위 테스트를 먼저 작성하고, 그 계약을 만족하는 구현을 추가한다.
6. 실제 OCR/PDF가 필요한 검증은 `integration` 또는 `poc` marker로 분리한다.
7. 시간과 필요한 메모리 지표를 기록한다. 대용량 POC에서는 청크별 RSS, 최대 RSS, GC 후 RSS, 단계별 시간을 기록한다.
8. 실패한 실제 페이지는 비식별화 가능한 최소 fixture로 만들고 회귀 테스트에 추가한다.
9. 결과와 다음 작업을 `docs/current_state.md`에, 설계 변경 이유를 `docs/decision_log.md`에 갱신한다.

## 테스트 작성 규칙

* 테스트 이름은 요구사항의 Test 번호와 기능을 반영한다.
* 단위 테스트에서는 네트워크와 실제 모델 서버를 호출하지 않는다.
* LLM 테스트는 JSON 파싱과 스키마를 우선 검증하며, 모델 품질 평가는 POC에서 별도 측정한다.
* PDF 페이지 누락·중복, OCR 실패, 빈 페이지, 회전 페이지, 잘못된 JSON, whitelist 오탐을 명시적 경계 케이스로 다룬다.
* 실제 원본 문서와 개인정보는 fixture 또는 저장소에 넣지 않는다.

## 완료 체크

- [ ] 단위 테스트가 독립적으로 재현 가능하다.
- [ ] 외부 엔진 의존 테스트가 marker로 분리됐다.
- [ ] 결과에 페이지 번호와 근거가 보존된다.
- [ ] 필요한 성능/메모리 지표가 기록된다.
- [ ] 현재 상태와 설계 결정 문서가 갱신됐다.
