# 근거 기반 AI 평가 지원 시스템 프로젝트 계획

## 목적

오프라인 환경에서 RFP, A권 제안서, B권 증빙자료를 분석해 정량·정성 평가와 페이지 근거를 제공하는 Tauri 데스크톱 앱을 완성한다. 최종 운용 환경은 Intel Core Ultra 계열 NPU 랩탑이며, 현재는 Python sidecar와 로컬 OpenVINO Gemma를 이용해 기능과 검증 체계를 먼저 확립한다.

## 현재 기준선

* Tauri UI는 사업 생성, RFP/A권/B권 PDF 선택, 평가 요청, 피드백, 결과 화면을 제공한다.
* Tauri는 `backend/.venv/bin/python -m api.server --port 8788`을 sidecar로 시작한다.
* sidecar는 텍스트 레이어 PDF에서 페이지별 텍스트와 위치정보를 우선 추출하고, 배점표의 명시적인 규칙으로 점수를 계산한다.
* 로컬 모델 `/home/user/develop/model/ko-gemma-2-9b-it-int4-ov`은 점수를 바꾸지 않고 코멘트와 300자 이하 인용만 생성한다. 실패 시 결과는 `rule_based_fallback`으로 명확히 표시한다.
* POC·대시보드·테스트 하네스는 `backend/`에 유지한다.

## 단계별 계획

### Phase 1 — 현재 연결 안정화

목표: UI에서 선택한 실제 PDF 한 건을 OpenVINO Gemma까지 일관되게 평가한다.

* sidecar 시작, PDF 경로 등록, 평가 작업 폴링의 오류 표시를 정리한다.
* 로컬 Gemma의 JSON 응답 실패·시간 초과·모델 로드 실패를 재현 가능한 테스트로 추가한다.
* 점수, 규칙 근거 페이지, 모델 인용 페이지, 코멘트 출처를 결과 화면에 표시한다.

완료 기준: 텍스트 레이어 PDF fixture에서 점수와 인용 페이지가 반환되고, UI가 `local_openvino_gemma` 또는 `rule_based_fallback` 상태를 표시한다.

### Phase 2 — RFP 평가표·체계규격 구조화

목표: 텍스트 PDF의 표에서 사업별 평가 규칙을 자동 추출한다.

* 문자 좌표와 표 선을 이용해 행·열, 병합 셀 및 페이지 간 연속 표를 복원한다.
* 평가항목, 배점, 계산식, 필수·일반 표식, 가감점, 불합격 및 증빙 요건을 구조화한다.
* 수치·단위·범위·수량과 AND·OR 복합조건을 판정 가능한 규칙으로 변환한다.
* 각 규칙을 RFP 원문 페이지와 영역 좌표에 연결하고 신뢰도를 기록한다.

완료 기준: 예시 RFP에서 체계규격의 항목, 필수·일반 구분, 가점 대상, 규격 원문 및 수량이 원문 근거와 함께 추출되고, 불명확한 표식은 자동 확정되지 않는다.

### Phase 3 — 선택적 OCR 통합

목표: 텍스트가 없거나 손상된 페이지와 이미지형 표를 평가 범위에서 누락하지 않는다.

* PaddleOCR 어댑터를 sidecar API에 연결한다.
* 텍스트 추출을 기본으로 하고 필요한 페이지·영역에 OCR을 적용한다.
* POC 비교를 위해 `all`, `fallback`, `text` 모드와 페이지별 텍스트 출처·렌더링 배율을 결과에 저장한다.
* OCR 실패 페이지와 재시도 결과를 UI에 노출한다.

완료 기준: 10~30페이지 실제 스캔 PDF에서 페이지 누락·중복 0건, OCR 출처와 실패 페이지가 모두 기록된다.

### Phase 4 — 세부 평가항목 단위 평가 기능 완성

목표: 권 구분이 아니라 RFP의 세부 판정 규칙에 따라 정량·정성 결과를 제공한다.

* 체계규격: 필수·일반 항목, 가점, 감점 및 불합격 후보 판정.
* B권: 참가 자격과 필수 증빙의 존재·유효성·일치 여부 판정.
* A·B권: 분량, 작성기준, 블라인드 및 감점 조건 판정.
* 정성항목: RFP 매칭, 근거 탐색, 세부요소별 코멘트, AI 잠정 등급 및 실제 인용 페이지 보존.
* 상대평가: 모든 업체 분석 완료 후 강제 배분 규칙을 적용한 참고용 등급 후보를 생성하고 평가위원 검토값과 분리.
* Test 06(RAG 인용)과 Test 07(컴플라이언스) POC 및 API 계약 추가.

완료 기준: 각 결과에 RFP 규칙, 제안서 근거, 계산 과정, 신뢰도, 검토 상태 및 재현 가능한 입력 설정이 포함된다.

### Phase 5 — 성능·운용 POC

목표: 목표 장비에서 수백 페이지 문서를 안정적으로 처리한다.

* 1~5 → 10~30 → 50~100 → 300페이지 이상 순으로 확장한다.
* 30·50페이지 청크, OCR 방식, 모델 디바이스 설정을 비교한다.
* RSS, 최대 RSS, 단계별 시간, OCR 정확도, 탐지 F1, 인용 페이지 정확도를 기록한다.

완료 기준: 300페이지 이상 문서를 동일 설정으로 3회 실행해 페이지 누락·중복 0건 및 확정된 메모리·시간·정확도 기준을 만족한다.

### Phase 6 — 배포 준비

목표: Windows NPU 랩탑에서 설치 가능한 오프라인 앱으로 만든다.

* Python 환경과 OpenVINO 모델을 Tauri sidecar 배포물로 패키징한다.
* 현재 개발용 `backend/.venv` 경로 의존성을 배포용 실행 파일/번들 경로로 대체한다.
* 심의 지원자료와 변경 이벤트를 로컬 SQLite에 저장하고 검토 스냅샷, 백업·복원 및 내보내기를 지원한다.
* 모델, OCR 모델, 개인정보 포함 원문·결과의 보존 및 삭제 정책을 확정한다.

완료 기준: 네트워크 없이 설치·실행·평가·결과 확인이 가능하다.

## 우선순위와 리스크

| 우선순위 | 항목 | 대응 |
|---|---|---|
| 높음 | 표의 필수·일반 표식 또는 행 연결 오류 | 좌표 기반 표 복원, 원문 영역 연결, 불확실 시 검토 요청 |
| 높음 | 이미지형 페이지의 텍스트 누락 | 선택적 OCR 및 페이지별 출처 저장 |
| 높음 | 로컬 모델 첫 로드 시간·메모리 | 지연 로드, 단일 인스턴스, POC 측정 |
| 높음 | 점수 재현성 | 배점표 규칙만 점수 산정, 모델은 설명만 생성 |
| 중간 | 모델 JSON/인용 오류 | JSON 검증, 300자 제한, 입력 페이지 재검증 |
| 중간 | 배포 경로 차이 | 개발·배포 sidecar 경로를 분리해 관리 |

## 문서 갱신 규칙

기능 또는 설계 결정을 변경하면 `docs/harness.md`의 현재 상태·검증 명령을 갱신한다. 장기 우선순위나 완료 기준이 바뀌면 이 문서를 갱신한다. POC에서 발견한 결함은 최소 fixture와 단위 테스트로 환원한다.
